Corrective RAG

A RAG system built as a graph, not a straight line. It retrieves documents, checks whether they actually answer the question, and — if not — rewrites the query and tries again. That loop is what a chain cannot do.

The Graph
The three exits from grade
relevant → generate
Docs answer the question. Claude writes the answer and the graph ends.
not relevant → rewrite
Docs miss. Rephrase the query and loop back to retrieve. Tries left.
out of tries → give_up
Retrieval keeps failing. Say so honestly instead of inventing an answer.

Why a graph, not a chain?

A chain is a straight line: retrieve → answer. It can't react when retrieval misses. A graph adds the one move a line can't make — a cycle back to retrieve — so it self-corrects until it has good context or gives up.

Five LangGraph concepts → where they live in the code
ConceptIn the codeWhat it is
State class ChatState(TypedDict) A shared dict that every node reads from and writes updates to.
Node contextualize, retrieve, grade, rewrite, generate, give_up A function: takes the state, returns the part of it to update.
Edge add_edge("retrieve", "grade") A fixed transition — “after this node, always go there.”
Conditional edge add_conditional_edges("grade", decide_next, …) A function picks the next node based on the current state.
Cycle add_edge("rewrite", "retrieve") Loops back to try again — the move a linear chain can’t express.
